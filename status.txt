DEFECTS FOUND THAT NOTHING WAS LOOKING FOR
=========================================================================
Each was invisible to every gate that existed at the time.

 1. OUR OWN ORACLE WAS LEAKING. eval/baselines.py saved PDFs without garbage collection,
    so greedy_redactor — the baseline every gate is calibrated against — leaked 62 real
    PII strings through revision residue while reporting itself clean. A leaky oracle
    miscalibrates every gate derived from it. FIXED.
 2. EVERY OUTPUT CARRIED A PICTURE OF PAGE ONE. python-docx ships docProps/thumbnail.jpeg
    in its default template and the writer copied it through byte-for-byte. It is pixels,
    so no text extractor can see it and no gate could ever have caught it. Now deleted.
 3. THE DIGIT/LETTER BOUNDARY. A regex \b does not sit between a digit and a letter, so
    the 8-digit IČO pattern never matched "43235222IBAN" — every numeric identifier was
    invisible when glued to a letter, which is what a PDF text layer produces at cell
    boundaries. On one corpus string the IBAN went undetected while the widened RČ
    pattern claimed a fragment of it. FIXED.
 4. A LINE BREAK INSIDE AN ANCHOR — AND IT LEAKED. A corpus PDF wrapped between the words
    of "Číslo klienta", so the anchor missed and the client number survived into the
    redacted text layer, while the DOCX of the same document was clean. FIXED.
 5. AN NBSP INSIDE AN ANCHOR — ALSO A LEAK, found by the demo. Same shape as 4. FIXED
    once in detect(), for every detector at once.
 6. A FAX NUMBER REPORTED AS A RODNÉ ČÍSLO. "055 123 4567" parsed as 6+4 digits and
    passed the month/day check. Redacted either way, but a report that mislabels what it
    removed cannot be checked against the document. FIXED.
 7. A CORPUS GROUND-TRUTH BUG OF MINE: DocxBuilder.header/footer overwrote earlier text
    while still recording it in ground truth, so GT claimed 30 surfaces that were not in
    the files — inflating recall for the vanished types. FIXED in the builder, so the
    invariant holds for every future template.
 8. A CONFIG FLAG THAT DID NOTHING — so EVERY DATE was being redacted. redact_all_dates
    had zero read sites: detect_datetime_amounts did not accept a config at all and emitted
    every DATUM with auto=True, while the contract and the module's own docstring both said
    only a date of birth was redacted. A contract is a chain of dates — signed on, effective
    from, payable by — and destroying all of them leaves a document nobody can use. Found
    because the GUI round REFUSED to ship a checkbox describing behaviour the engine did not
    have, and left a tripwire that forced the text to be corrected when the engine was fixed.
    FIXED: birth-anchored dates are auto, every other date goes to review, the flag works.
 9. TWO OF MY OWN CONTRACT CLAUSES WERE WRONG, and a round refused to implement one of
    them (deleting the BANKOVY_UCET suppressor would have made strict_checksums a silent
    no-op for every legacy account number). Both retracted — CONTRACTS_v11.md Am. 2, 3.
